# 星系类型筛选：170671 离线核对

2026-09-09。正式版 v1.1.1 基于已实测的 rc3。下面保留各阶段分类布局、光谱和标签证据，末尾记录 rc3 的游戏实测结果。

基于已发布的 v1.1.0 GUI 源码。没有恢复生态扫描，也没有增加原生函数入口。原选星路径已经调用 `0x1216440`，给 `warp_check` 提供 48 字节的星系属性；筛选启用时读取这个现有结果，在能力检查和选中目标之前排除不匹配项。关闭筛选不解析这些字段，不增加分类调用次数。

## 布局证据

- 游戏 EXE SHA-256：`ea7e5a29bbf931f96ae8dda81553353aab3431dc38e4ed7dfb66bdce100770e3`。
- [NMS.py 类型定义](https://github.com/monkeyman192/NMS.py/blob/886a149e5aa7873777fc2fa14b73dc0c516cf794/nmspy/data/types.py)：`cGcGalaxyAttributeGenerator.StarSystemKeyAttributes`，大小 `0x30`；颜色 `+0x10`，居民种族 `+0x0C`，废弃 `+0x24`，海盗 `+0x25`。
- [NMS.py 枚举](https://github.com/monkeyman192/NMS.py/blob/886a149e5aa7873777fc2fa14b73dc0c516cf794/nmspy/data/enums/external_enums.py)：黄色 0、绿色 1、蓝色 2、红色 3、紫色 4；无人种族 `None_=7`。
- 本机磁盘反汇编：`0x1216440` 在 `0x1216920` 调用 `0x1216950`。后者将输出指针保存到 RBP；`0x121725D` 等位置按 `+0x10` 索引颜色配置；`0x1217285` 写废弃标志，`0x12173E7` 明确按 `+0x10 == 4` 处理紫色恒星。
- `0x1217359` 从星系生成配置 `+0x184` 读取概率（公开类型中为 EmptySystemProbability），满足时 `0x1217368` 将输出 `+0x0C` 写为 7。无人判断优先于保留的废弃标志，避免把无人星系误算成普通/废弃星系。
- `0x1217483` 排除已废弃星系，`0x1217489` 排除无人种族；`0x12174BC` 才将 `+0x25` 写为 1。因此海盗标志与无人或废弃同时出现时作为未知/冲突数据停止。

原始离线文本保存在 `research/star-filter-prep-disassembly.txt` 和 `research/star-filter-classify-disassembly.txt`，不作为运行依赖。静态证据与模拟字节测试不能代替游戏内验收。

## 行为

总开关默认关闭；开启后光谱字母、数字、后缀、类别、地图标签和主导种族六组分别至少选择一项。组内多选为“或”，组间为“且”。连接前设置，随后本次运行固定；下一轮仍使用相同选项。每轮至多尝试配置指定的 256 个候选，找不到可达匹配项时停止，不放宽条件。不绕过游戏原有能力检查、范围或解锁条件。

记录类别、颜色、筛掉的候选数量及选中结果，不记录星系地址、坐标或名称。原有已选目标一致性、暂停、停止和加载检查继续执行。正式 v1.1.0 Release 保持不变，本地 RC10 已归档到 `build/archive-rc10-20260909`。

## rc2 光谱计算

本机固定 EXE 的 `0x151AA40` 根据 seed 和颜色生成字母、数字与后缀，结束于 `0x151AE6D`。本版将整数算法写成纯 Python，没有绑定或调用这个入口。

- 银河地图 `0x1249131` 读取面板 `+0x5D0` 作为 seed，`0x124913D` 读取 `+0xA4C` 的颜色，`0x1249156` 调用该格式化函数。
- 64 位两次混合乘数为 `0x64DD81482CBD31D7` / `0xE36AA5C613612997`，移位 33；RNG 是以 `0x5A76F899` 为乘数的 32 位状态与进位。
- 各非绿色分支先取一个随机数，低位奇数对应 F/M/O/X，偶数对应 G/K/B/Y；绿色固定 E 且不消耗这次抽取。字符串地址：F `0x47A726C`、G `0x47899CC`、M `0x47B33DC`、K `0x47B7664`、E `0x47EE1E4`、O `0x48333D4`、B `0x47899D0`、X `0x47899B8`、Y `0x47899BC`。
- `0x151AD9B`～`0x151ADA2` 将下一次抽取值乘 10 后右移 32 得到 0～9。随后抽取的低位决定 p，进位减低位的奇偶决定 f；输出顺序为 p 然后 f。两者都无即无后缀。
- 记录计算所得光谱，不将光谱数字解释为行星温度或宜居程度。原始离线记录 `star-spectrum-151AA40.txt`、`star-map-spectrum-caller.txt`。

## rc2 地图现有标签读取

不调用行星生成、不申请临时行星对象。仅在原选星流程结束、原有就绪门槛成立后读取游戏正常地图面板中的数据。

- `select_star` 在 `0x122722C` 取 map `+0x2190`，`0x122723D` 调用 `0x1243380`，后者把查询及分类结果复制到面板 `+0x600`。
- 地图更新 `0x121EBBF` 传 map `+0x2190` 给 `0x1241480`；该函数在 `0x124149A` 再加 `0x30` 调用 `0x1247AE0`。因此下列渲染子面板相对 map 偏移是 `0x21C0`，不能直接套用父面板偏移。
- 子面板 query `+0x5D0`、已处理 query `+0x5C0`、颜色 `+0xA4C`、四个连续标志 `+0xA80`。现有 map_popup_state（map `+0x26C4`）对应子面板 `+0x504`，状态 3 是生成完成后的显示分支。
- 标签更新 `0x1248227` 写水、`0x124825E` 写不协、`0x124826B` 写气态巨行星、`0x12482B3` 写蠕虫。在 `0x12482BC` 更新 UI 后，`0x12482DB` 复制当前 query 为已处理 query，随后设状态 3。
- `0x124919B` 及后续渲染分支按气态巨行星、蠕虫、不协、水的优先级只添加一个标签。对应 EXE 的本地化键 `UI_GALMAP_GAS_GIANT`、`UI_GALMAP_WORM_LABEL`、`UI_GALMAP_CORRUPTION`、`UI_GALMAP_WATER`；不是把所有存在的属性都算作可见后缀。全部为零即无附加标签。
- 子面板 `+0xA9A` 是会在下一帧清除的音效触发标志，**不是**就绪标志，不纳入读取条件。
- 等待当前与已处理 query 一致，核对实际所选星系和光谱/颜色。旧面板数据只等待，不放行；非法布尔标志或分类不一致则停止。发起跃迁前再次读取，防止标签变化后仍使用旧证明。
- 后缀拒绝回到候选搜索，同一轮候选次数保持累积，到上限停止。日志先写初筛候选（pending_confirmation），完整标签检查后写 `star_filter_verified`；只有后者显示“目标筛选通过”。

## rc3 独立种族筛选与 rc2 运行证据

用户撤回了勾选无人时清空/禁用种族组的规则。类别中的无人表示允许候选类型之一，并不独占整组。现在两组始终独立，默认各组全选，种族增加 `none`（无主导种族）；界面、模型和参数序列化均不再自动删除种族条件。

确认依据：公开枚举 `cGcAlienRace.None_ = 7`，本机分类函数 `0x1217368` 在无人分支写 `+0x0C = 7`。2026-09-09 07:23～07:29 的 rc2 会话还实际解码出 19 条 `category=empty, race=none` 候选记录；它们都被当轮筛选拒绝。日志未记录名称/坐标，不能推断 19 个互不相同的星系。

该会话完成 10 轮跃迁/扫描、48 次行星提交，152 次候选尝试；10 个放行目标均在配置限定的字母、数字、类别、种族及标签内。地图标签复核还拒绝过 1 个无附加标签目标。自动上传本地处理 4 批共 39 条记录。没有错误或日志丢弃，F3 正常停止。全部放行标签为水，不代表气态巨行星筛选已实测；后缀全选，不代表单一后缀限制已实测。摘要和 19 条候选明细在 `star-filter-trial-20260909T0723.json`。

rc3 只修改选项、匹配及 GUI 行为，不修改原生扫描/跃迁路径或增加原生入口。97 项非游戏测试、Ruff、compileall 及 Tk DPI 144 检查通过，包含无人切换不丢失现有种族、无主导种族可与吉克混选、独立 AND/OR 筛选和 CLI 往返。发行包单独生成，旧 rc2 包和日志保留。本轮不连接游戏、不发布 GitHub。
