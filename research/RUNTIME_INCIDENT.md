# 首次连接失败和修复记录

## 已观察到的事实

- 用户已打开测试存档且窗口未最小化，授权继续观察测试。
- 目标 PID 2780，EXE 哈希与 profile 一致，六个选用签名通过静态核查。
- 启动前发现 pyMHF 0.2.4 的完成回调会调用 os.kill 结束被连接进程。已在独立函数作用域适配此行为，禁止进程终止，并固定按 PID 连接。
- 首次普通管道启动遇到无控制台错误，尚未注入；随后在终端环境中启动，沙箱拒绝访问游戏进程。用户批准在沙箱外以当前用户权限运行，不使用管理员权限。
- 运行时进入 NMS.exe 后，在 `_preinject.py` 报 `ModuleNotFoundError: No module named 'pymhf'`。观察模块和游戏钩子未启用。
- 2026-09-03 06:59:25 的 Windows Application Error 1000：NMS.exe，PID 0xADC（2780），故障模块 python312.dll，异常 0xc0000005，模块偏移 0x172230。
- 没有自动游戏动作或存档文件读写。不能据此保证未保存的游戏进度没有损失。

导入失败后的运行时结束是可疑故障路径：pyrun-injected 0.2.0 在脚本结束/失败后调用 Py_FinalizeEx。事件日志证明故障模块是注入的 Python，但目前没有完整原生调用栈来证明崩溃发生于哪条清理指令，不应将假设写成已经确认的精确根因。

## 修复方式

本项目的 `attach_framework.py` / `runtime_bootstrap.py` 适配固定版本框架，未修改第三方安装文件：

1. 在入口函数的独立全局字典中限制进程选择和终止行为，不全局替换 os 或 pymem。
2. 正确提供运行时需要的 EXE 名称，同时实际连接仍固定到已核查 PID；观察模块再次核对 PID。
3. 使用 DummyInput / DummyOutput 的应用上下文导入 pyMHF，避免依赖可见控制台。
4. 使用标准化导入路径，把初始化内容包装为单段脚本，确保共享作用域。
5. 初始化异常写入项目日志；若框架退出则停止已有观察记录，并保持 Python 驻留，不返回到底层解释器清理路径。完全卸载仍需用户退出游戏。

这避免了已知的进程终止和初始化清理风险，不能防止错误 ABI、游戏对象失效等所有可能的原生崩溃。普通货船跃迁和自动扫描仍未开放。
